# Open-source AliExpress affiliate bots and tools: survey of architecture, ratings and review counts, and patterns (as of Oct 2026)

Method: GitHub repo and code search through the `gh` CLI (stars and push dates read from the GitHub API on 2026-10-22), then I read the actual source files of about 15 repos. A few web sources were added. Star counts are small across this whole niche. Even the most-starred actual bot has only 40 stars, so "best" here means best engineered, not most popular.

## 1. Which repos exist (Telegram/WhatsApp/Discord AliExpress affiliate bots), with stack, stars, last update, and features?

### Takeaway
There are dozens of small AliExpress affiliate Telegram bots on GitHub, mostly Python, mostly Arabic/Maghreb "coin discount" link-converters, and almost all under 10 stars. Only two Hebrew search bots were found. One of them (omerxxben/telegram_bot) is architecturally almost exactly the target product: a "חפש לי" trigger, Gemini translation and relevance filtering, ratings and review counts from the DS API, and a Pillow medal collage. Shared SDKs (`python-aliexpress-api`, `ae_sdk`) are the real backbone. I found no WhatsApp bot repos and only one trivial Discord repo.

### Inferences
- The niche is dominated by copy-paste link converters, often generated from YouTube tutorials or with AI help. Popularity (stars) is not a quality signal. The engineering quality is in djeddi12 (link handling and caching), omerxxben (search, ranking and collage) and shopli (API behavior notes).
- omerxxben/telegram_bot is the closest existing reference implementation for a Hebrew group "חפש לי" bot with a 2x2/medal collage and "⭐ X (N ביקורות)" lines. It is worth studying, then fixing its weaknesses (section 7).
- The lack of WhatsApp repos fits with WhatsApp bots being harder to run (official Cloud API cost, or unofficial libraries that risk bans). That is my inference, not sourced.

## 2. How do they get review count and star rating ("4.9 from 44 reviews")? Which approaches work in 2025–2026?

### Takeaway
The standard affiliate API (`product.query`, `productdetail.get`) does **not** return a star rating or a review count. It only returns `evaluate_rate`, a positive-feedback percentage string such as "96.5%", plus `lastest_volume`. Projects that show real "4.9 (44)" data get it one of two ways:
- (a) The **Dropshipping API `aliexpress.ds.product.get`**, using `ae_item_base_info_dto.avg_evaluation_rating` and `.evaluation_count`. This needs a separate DS app and an OAuth access_token. omerxxben does this.
- (b) The **undocumented keyless endpoint `feedback.aliexpress.com/pc/searchEvaluation.do`**, using `productEvaluationStatistic.evarageStar` (sic) and the star histogram. shopli and fetchaller used it in Aug–Oct 2026.

Scraping product-page HTML (`window.runParams`) no longer works with plain HTTP, because pages are client-rendered and MTop is captcha-gated.

### Cited Findings
- The affiliate Product model in python-aliexpress-api exposes `evaluate_rate: str` and `lastest_volume: int`, and no rating or review-count field. — [models/product.py](https://github.com/sergioteula/python-aliexpress-api/blob/HEAD/aliexpress_api/models/product.py); the same two fields are in ae_sdk's [types/affiliate.ts](https://github.com/moh3a/ae_sdk/blob/HEAD/src/types/affiliate.ts)
- shopli (Aug 2026): "The affiliate API gives us a positive-feedback percentage and nothing else — no review text, and (verified 2026-08-15 against a live response) no `last_5_days_trade_count` field". Its earlier `reviewCount` therefore made "every product on the site claim 0 reviews". It parses `evaluate_rate` with `.replace('%','')` and treats it as 0–100. — [lib/reviews.ts](https://github.com/ohadf2015/shopli/blob/HEAD/lib/reviews.ts), [lib/aliexpress.ts](https://github.com/ohadf2015/shopli/blob/HEAD/lib/aliexpress.ts)
- The DS API response type includes `evaluation_count: string; avg_evaluation_rating: string` in `DS_Product_Base_Info`. — [ae_sdk types/ds.ts](https://github.com/moh3a/ae_sdk/blob/HEAD/src/types/ds.ts)
- omerxxben calls `aliexpress.ds.product.get` on `https://api-sg.aliexpress.com/sync` with `access_token`, a separate `DS_APP_KEY`/`DS_APP_SECRET`, `target_currency=ILS`, `target_language=he` and `ship_to_country=IL`. It reads `aliexpress_ds_product_get_response.result.ae_item_base_info_dto.{avg_evaluation_rating, sales_count, evaluation_count, subject}`, fanned out with ThreadPoolExecutor(max_workers=10) and a 0.1 s spacing. The Hebrew caption template is `'[אייקון_כוכב] [דירוג] ([כמות_ביקורות] ביקורות)'`. — [ali_epress_api_products.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/ali_epress_api_products.py), [telegram_bot_manager.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Telegram/telegram_bot_manager.py)
- The project needs both affiliate keys and DS keys, plus an `AUTH_CODE`: its env vars are `APP_KEY`, `APP_SECRET`, `SECOND_APP_KEY`, `SECOND_APP_SECRET`, `AUTH_CODE`, `DS_APP_KEY`, `DS_APP_SECRET`. — [GLOBAL_CONST.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/GLOBAL_CONST.py)
- **Feedback endpoint (keyless):** `https://feedback.aliexpress.com/pc/searchEvaluation.do?productId=…&lang=he_IL&country=IL&page=1&pageSize=20&filter=all&sort=complex_default`. shopli says: "Without a browser UA this endpoint answers with an interstitial." It sends a Chrome UA and `Referer: https://www.aliexpress.com/`, uses a 4 s timeout, and returns null on failure. `lang=he_IL` returns machine-translated Hebrew reviews plus buyer country, variant and photos. — [lib/reviews.ts](https://github.com/ohadf2015/shopli/blob/HEAD/lib/reviews.ts)
- **Two different denominators** on the feedback endpoint: "`totalNum` 1186 … → reviews with TEXT" versus "fiveStarNum+…+oneStarNum = 6814 → all RATINGS". The histogram "is filtered upstream" (1-star and 2-star counts were 0 while 557 ratings sat at 3 stars), so it "must not be used to claim 'we screen out products with bad reviews'". `buyerEval` is 0–100 in steps of 20. — [lib/reviews.ts](https://github.com/ohadf2015/shopli/blob/HEAD/lib/reviews.ts)
- fetchaller (Oct 2026) uses the same endpoint (`lang=en_US`, `country=US`, item Referer) through its `wafer` anti-bot session. "An item with no reviews reports `totalNum: 0` and `evarageStar: 0.0`; it renders as 'no reviews yet', never as a zero-star rating." — [reviews.py](https://github.com/Averyy/fetchaller-mcp/blob/HEAD/src/fetchaller/aliexpress/reviews.py), [site-apis.md](https://github.com/Averyy/fetchaller-mcp/blob/HEAD/docs/site-apis.md)
- Scrapfly's scraper reads `data.totalPage`, `data.evaViewList` and `data.productEvaluationStatistic` from the same endpoint. — [scrapfly aliexpress.py](https://github.com/scrapfly/scrapfly-scrapers/blob/HEAD/aliexpress-scraper/aliexpress.py)
- **Page scraping status (Oct 2026):** "Product pages are CSR (`isCSR: true`). `window.runParams` is declared empty — full modules come from MTop `mtop.aliexpress.pdp.pc.query`". "MTop answers a distrusted session with a Google reCAPTCHA, even on the token bootstrap (observed 2026-10-05)". In a Linux container, "every fresh session drew the reCAPTCHA on 2026-10-08", while a cold read on macOS drew none. — [fetchaller site-apis.md](https://github.com/Averyy/fetchaller-mcp/blob/HEAD/docs/site-apis.md)
- Search-page SSR data can still be scraped from a `_init_data_ = { data: {...} }` script blob (Scrapfly regex), but Scrapfly scrapes product pages with `render_js=True` and a residential proxy pool. — [scrapfly aliexpress.py](https://github.com/scrapfly/scrapfly-scrapers/blob/HEAD/aliexpress-scraper/aliexpress.py)
- A third-party Apify actor gets aggregate `averageStar`, `averageStarRate` (positive %) and `reviewCount` from the "unsigned `shoprenderview.aliexpress.com` gateway". It notes "Per-buyer review TEXT is Baxia-gated" and that the gateway "sometimes serves a Baxia x5secdata challenge on first hit from a fresh IP"; residential proxies are recommended. — [Apify xtracto/aliexpress-review-scraper](https://apify.com/xtracto/aliexpress-review-scraper.md)
- shopli deliberately builds its quality gate on affiliate fields rather than the review endpoint: "a gate that depends on it turns one bad afternoon at feedback.aliexpress.com into empty collection pages sitewide." Measured thresholds over 395 IL products (2026-08-15): `evaluate_rate >= 90` keeps 87%, `>= 94` keeps 65%, and `lastest_volume >= 100` keeps 98%. It chose a 90/100 floor and uses 94+ as a "top" badge tier. — [lib/quality.ts](https://github.com/ohadf2015/shopli/blob/HEAD/lib/quality.ts)
- Common mistake: ismailsaoulaj does `float(evaluate_rate)` and displays `⭐ {rating}/5`. Its `_safe_float` returns 0.0 on ValueError, so a "%"-suffixed value becomes 0 and the rating line and 30% of the score silently die (or would show "96.5/5" if the value were unsuffixed). — [deals_api.py](https://github.com/ismailsaoulaj/aliexpress-affiliate-bot/blob/HEAD/deals_api.py), [bot.py](https://github.com/ismailsaoulaj/aliexpress-affiliate-bot/blob/HEAD/bot.py); format evidence from [shopli](https://github.com/ohadf2015/shopli/blob/HEAD/lib/aliexpress.ts)
- tzahi1715's Hebrew bot shows no rating at all. MiilouDz, djeddi12 and mouad73 show no rating either, only title, price and links. — the source files listed in section 1

### Inferences
- For "4.9 מתוך 44 ביקורות", the most robust approach is **DS `ds.product.get` (official, signed)** as the primary source, with the **feedback endpoint** as an enrichment or fallback. If neither is available, show `evaluate_rate` honestly as "96% משוב חיובי" rather than converting it to stars.
- DS-API calls are one per product, so fetch them only for the final shortlist (top 4–9), not all 50 search results. omerxxben calls them for every AI-filtered product.
- Label carefully: DS `evaluation_count` versus the feedback endpoint's `totalNum` (text reviews) versus the histogram sum (all ratings) can differ a lot (1,186 vs 6,814 on one product).

### Gaps
- I could not fetch the official Open Platform docs page for `aliexpress.ds.product.get` (it is JS-rendered), so I could not confirm the exact field semantics. For example, does `evaluation_count` count text reviews or all ratings? The DS token lifetime and refresh flow are also unconfirmed.
- I found no first-hand 2025–2026 report on blocking rates for `feedback.aliexpress.com` from cloud IPs. shopli implies it works with a browser UA, and fetchaller routes it through an anti-bot client.
- RapidAPI "AliExpress DataHub" field names (`averageStar`, `totalCount`) could not be verified. A search returned no listing.

## 3. How do they handle Hebrew or non-English queries? Do any use AI/LLMs for relevance or ranking?

### Takeaway
Every Hebrew bot translates the query to English before `product.query`. Methods range from the unofficial Google `translate_a/single?client=gtx` endpoint plus a hand-made gender/color dictionary (tzahi), to Google with an OpenAI fallback (Igusman), to Gemini 2.5 Flash-Lite with an e-commerce-tuned prompt (omerxxben). omerxxben also uses the LLM as a **strict relevance filter**, rejecting accessories. shopli uses an LLM batch job to rewrite garbled Hebrew titles. Ranking is otherwise heuristic: sales volume, min-max normalized rating, review count, and price.

### Cited Findings
- tzahi1715: `translate.googleapis.com/translate_a/single` with `client=gtx`, `sl=he`, `tl=en`. It then prepends gender words from GENDER_MAP ("לגבר"→"men", "לילדה"→"kids girl") and appends colors from COLOR_MAP, and strips leftover Hebrew characters with `re.sub(r'[א-ת]+','',…)`. It also translates each result title back to Hebrew with one HTTP call per product. — [bot.py](https://github.com/tzahi1715-cpu/aliexpress-telegram-bot/blob/HEAD/bot.py)
- Igusman: provider order `["google","chatgpt"]` via `deep_translator.GoogleTranslator`, noting "Google Translate uses 'iw' for Hebrew". OpenAI is the fallback with `OPENAI_MODEL` defaulting to `gpt-4o`. — [services/translation.py](https://github.com/Igusman/aliexpress-bot/blob/HEAD/services/translation.py)
- omerxxben: it detects Hebrew by the Unicode range `֐-׿` and skips translation if none is found. It calls Gemini `gemini-2.5-flash-lite-preview-06-17` with `thinking_budget=0`, temperature 0.1 and a system prompt to "Optimize the translated term for AliExpress search … Using common product terminology that sellers on AliExpress typically use". — [ai_manager.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/ai_manager.py)
- omerxxben's relevance filter sends all ~50 titles in one prompt: "only return 0 (suitable) if the product IS the actual item being searched for, not accessories, parts, or related items … Return ONLY a JSON object {"0": 0, "1": 1, …}". It strips code fences from the response, and if JSON parsing fails it returns an empty result, which means "no results" for the user. — [ai_manager.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/ai_manager.py)
- omerxxben's ranking (`getRank.calculate`) min-max normalizes rating, ratingCount, saleCount and price. Quality = 0.33·rating + 0.33·ratingCount + 0.34·sales, and grade = 0.5·quality + 0.5·(inverse price). The live pipeline in main.py, however, only calls `sort_by_volume` (by `lastest_volume`) before the AI filter. — [get_rank.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/get_rank.py), [main.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/main.py)
- ismailsaoulaj ranks deals as volume (capped at 10,000)·0.4 + discount·0.3 + rating/5·0.3. — [deals_api.py](https://github.com/ismailsaoulaj/aliexpress-affiliate-bot/blob/HEAD/deals_api.py)
- shopli: `target_language=HE` "returns literal machine translations of keyword-stuffed listing titles ('TIMEMORE צרפתי עיתונות עיתונות, מכונת קפה תה')", which reads as spam to native speakers. The fix is a cron job that has an LLM rewrite each title into "a short natural Hebrew title" and caches it per product_id in Postgres (Neon), failing open to the sanitized API title. — [lib/hebrew-titles.ts](https://github.com/ohadf2015/shopli/blob/HEAD/lib/hebrew-titles.ts)
- The achiya-automation n8n bot uses an "AI query builder" step to turn free-form Hebrew into a search query (LLM not named). — [case study](https://achiya-automation.com/en/case-studies/aliexpress-telegram-affiliate/)
- tzahi1715 picks a **random** page from 1–5 and a random sort from `LAST_VOLUME_DESC`/`SALE_PRICE_ASC`, then shuffles results. This hurts relevance and reproducibility. — [bot.py](https://github.com/tzahi1715-cpu/aliexpress-telegram-bot/blob/HEAD/bot.py)

### Inferences
- The proven pattern is: LLM translation into "AliExpress seller vocabulary", then `product.query` with `ship_to_country=IL` and a sales-based sort to get about 50 candidates, then an LLM relevance filter (strict, no accessories), then a heuristic ranking on rating, review count and sales. A cheap, fast model is enough for both LLM steps.
- Titles shown to Hebrew users should be LLM-shortened rather than taken from `target_language=HE`, and cached per product.
- The relevance step should fail open (fall back to the top-N by volume) rather than returning "no results" on a JSON parse error, as omerxxben does.

### Gaps
- No project published measured relevance or latency numbers for the LLM steps. omerxxben logs timings but no results are published.

## 4. How do they build the 2x2 collage with numbered or medal badges, versus Telegram media groups?

### Takeaway
Only omerxxben builds a composite image: Pillow, 800x800, a custom background, rounded frames with shadows, PNG medal badges, and RTL placement (rank 1 on the right). It sends one `send_photo` per page with a text caption and an inline "more results" button. Every other bot sends one `sendPhoto` per product, or a single photo. No repo used `sendMediaGroup`, which fits the fact that media groups cannot carry inline buttons.

### Cited Findings
- `ImageGridCreator(grid_size=(800,800))`, with layouts for 1, 2 and 3 images per page. For 3: rank 1 top-right, rank 2 top-left, rank 3 bottom-center. For 2: "Position right-to-left: First image (higher rank) goes right". Images are framed with `rounded_rectangle`, an alpha mask and a drop shadow. Medals come from `emojis/{rank}.png` files pasted with alpha, and the output is PNG to BytesIO. — [image_grid_creator.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/image_grid_creator.py)
- The bot sends the page with `context.bot.send_photo(..., reply_to_message_id=original_message_id)` and an InlineKeyboard button "עוד תוצאות 🔍" with `callback_data=f"nav:{next_page}:{user_id}:{search_id}"`, capped at page index 9. — [telegram_bot_manager.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Telegram/telegram_bot_manager.py)
- Images are downloaded **sequentially** with `requests.get(url, timeout=10)` per image inside the grid build. A failed download becomes an "Image Not Found" placeholder. — [image_grid_creator.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/image_grid_creator.py)
- Bug: `create_medal_or_number` has no number-drawing fallback. If the medal PNG is missing it returns `None` (the comment says "Fall through to number drawing" but there is none), and the next `paste(medal, …)` would fail. — [image_grid_creator.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/image_grid_creator.py)
- Per-product photo pattern: tzahi1715 sends up to 5 `sendPhoto` messages with a 2 s sleep between them, and MiilouDz and djeddi12 send a single product photo with a caption. — [tzahi bot.py](https://github.com/tzahi1715-cpu/aliexpress-telegram-bot/blob/HEAD/bot.py), [MiilouDz bot.py](https://github.com/MiilouDz/Aliexpress-Affiliate-Telegram-Bot/blob/HEAD/bot.py)
- Telegram Bot API: `sendMediaGroup` takes 2–10 items and its parameter list has `reply_parameters` but **no `reply_markup`**. The `sendPhoto` caption is limited to "0-1024 characters after entities parsing", and photos to 10 MB. — [Bot API](https://core.telegram.org/bots/api#sendmediagroup), [sendPhoto](https://core.telegram.org/bots/api#sendphoto)

### Inferences
- A single collage plus caption plus inline keyboard is one message instead of 4–5. That works better in groups because of the 20 messages/min group limit (section 6), and it allows a "more" button. A media group would need a separate follow-up message for buttons.
- The 1,024-character caption limit constrains a 4-product caption with titles, ⭐ rating (count), price and links. Short LLM titles help here. Inline URL buttons per product (1️⃣ 2️⃣ 3️⃣ 4️⃣) are an alternative to long links in the caption (inference).
- Download images concurrently (asyncio/aiohttp), request AliExpress image thumbnails rather than full-size images, and draw the number badges with Pillow text as a fallback. Pillow's default text rendering cannot draw color emoji, which is presumably why PNG medals were used (inference).

### Gaps
- No Node/sharp-based collage implementation was found to compare against.
- I found no measured collage build times.

## 5. How do they convert pasted links (including a.aliexpress.com and s.click short links) to affiliate links?

### Takeaway
The proven pipeline (djeddi12 and mouad73) is: regex-extract URLs, including short domains → follow redirects (`allow_redirects=True`) → normalize the domain (.us→.com) and ship-to country → extract the product ID with `/item/(\d+)\.html` (plus `productIds=` for coin pages) → rebuild a clean item URL → call `aliexpress.affiliate.link.generate`, batching comma-separated `source_values`, and cache. Many Arabic bots also wrap the URL in `star.aliexpress.com/share/share.htm?…redirectUrl=…&sourceType=NNN` to produce "coin", "super deal" and "limited" variants. These sourceType codes are undocumented community folklore.

### Cited Findings
- djeddi12 regexes: `SHORT_LINK_DOMAIN_REGEX = https?://(?:s\.click\.aliexpress\.com/e/|a\.aliexpress\.com/_)[a-zA-Z0-9_-]+/?`, `PRODUCT_ID_REGEX = /item/(\d+)\.html`, and a multi-TLD AliExpress domain regex. — [app.py](https://github.com/djeddi12/Aliexpress-telegram-bot/blob/HEAD/app.py)
- djeddi12 `resolve_short_link`: aiohttp GET with `allow_redirects=True` and a 10 s timeout. It converts `.aliexpress.us` to `.aliexpress.com`, rewrites `_randl_shipto=` to the configured country and **re-fetches** "to get the correct product ID", validates that the result is a real product URL, and caches the resolution for 1 day. — [app.py](https://github.com/djeddi12/Aliexpress-telegram-bot/blob/HEAD/app.py)
- djeddi12 batch link generation: it checks the cache first, prefixes uncached URLs with `https://star.aliexpress.com/share/share.htm?&redirectUrl=`, and makes one `aliexpress.affiliate.link.generate` call with comma-joined `source_values`. — [app.py](https://github.com/djeddi12/Aliexpress-telegram-bot/blob/HEAD/app.py)
- Offer variants in djeddi12: coin `sourceType=620&channel=coin`, super `562`/`sd`, limited `561`/`limitedoffers`, bigsave `680`/`bigSave`, all with `afSmartRedirect=y`. mouad73 uses a coin-index URL `m.aliexpress.com/p/coin-index/index.html?…productIds={id}` and a "bundle" `sourceType=560`. — [djeddi12 app.py](https://github.com/djeddi12/Aliexpress-telegram-bot/blob/HEAD/app.py), [mouad73 Bot.py](https://github.com/mouad73/AliexpressTelegramBotBasic/blob/HEAD/Bot.py)
- mouad73 `resolve_full_redirect_chain` follows redirects and, if the final URL has a `redirectUrl` query param, unwraps it. It also handles `p/coin-index` pages by extracting `productIds=(\d+)`. — [Bot.py](https://github.com/mouad73/AliexpressTelegramBotBasic/blob/HEAD/Bot.py)
- For search results, omerxxben feeds the `promotion_link` values returned by `product.query` into `link.generate` with `promotion_link_type=2` to get short links, deduped and batched. On `ApiCallLimit` it waits 5 s, re-signs with a new timestamp, and retries up to 3 times. — [ale_express_api_short_link.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/ale_express_api_short_link.py)
- shopli: "A `promotion_link` (s.click...) already converts". If a link is already tagged (s.click deep link or an `aff_*` param), it leaves it untouched. — [lib/aliexpress.ts](https://github.com/ohadf2015/shopli/blob/HEAD/lib/aliexpress.ts)
- A suspicious pattern in platoba/MultiAffiliateTGBot: it builds `https://s.click.aliexpress.com/e/{aff_id}?url={quote(url)}` locally instead of calling link.generate. I found no documentation supporting this format. — [app/platforms/aliexpress.py](https://github.com/platoba/MultiAffiliateTGBot/blob/HEAD/app/platforms/aliexpress.py)
- Admitad's bot notes that it "doesn't check if an AliExpress product is available for affiliate marketing". In other words, not every product is affiliate-eligible. — [Admitad KB](https://admitad.useresponse.com/knowledge-base/article/admitad-bot-for-telegram_5)

### Inferences
- Always resolve short links server-side and extract the numeric ID. Then generate the link from a **clean** `https://www.aliexpress.com/item/{id}.html` (not from the user's tracking-laden URL), so a competitor's affiliate tag is not just passed through.
- The sourceType "coin/super/limited" trick is undocumented and could break or be treated as abuse at any time. Use it only as an optional extra (inference).
- Cache resolved-URL→ID and ID→affiliate-link mappings (djeddi12 uses 1 day). Product IDs are stable, but prices are not.

### Gaps
- I found no official documentation for `sourceType` codes or the `star.aliexpress.com/share/share.htm` wrapper. Their commission effect is unverified.

## 6. Group behavior: triggers ("חפש לי"), reply-to, rate limiting per user, anti-spam, caching

### Takeaway
omerxxben uses prefix triggers `['חפש לי','מצא לי']`, replies to the original message, and restricts "more" to the requester (callback data carries user_id and search_id). It keeps the last 10 searches in `user_data`. However, it replies with a help message to **every** non-trigger text, which is spam in a group, and it has no per-user rate limit. Per-user token buckets (platoba) and caching (djeddi12: 1-day TTL; shopli: CDN and DB) exist in other repos. Telegram itself limits bots to about 20 messages/min per group, and privacy mode hides normal group messages unless the bot is an admin or privacy mode is disabled.

### Cited Findings
- omerxxben: `'activation_keywords': ['חפש לי', 'מצא לי']` matched with `message_text.startswith(keyword)`. Non-trigger messages get `'no_activation': 'לחיפוש, יש להקליד \'חפש לי...\'…'`. It sends a "מחפש עבורך... אנא המתן 🔍" placeholder and deletes it afterwards. The callback handler rejects other users with `'unauthorized_click': 'רק מי שביקש את חיפוש זה יכול לבקש עוד מוצרים 😊'`. Searches are stored in `context.user_data['searches']`, trimmed to the last 10, with a `'search_expired'` message. — [telegram_bot_manager.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Telegram/telegram_bot_manager.py)
- omerxxben runs the whole synchronous pipeline (requests, Gemini, ThreadPool, Pillow) directly inside the `async` handler (`MainProducts().process(product_name)`), which blocks the event loop for all chats during a search. djeddi12, by contrast, wraps blocking SDK calls in `loop.run_in_executor(executor, …)`. — [omerxxben telegram_bot_manager.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Telegram/telegram_bot_manager.py), [djeddi12 app.py](https://github.com/djeddi12/Aliexpress-telegram-bot/blob/HEAD/app.py)
- tzahi1715 strips the bot mention (`text.replace("@Isradeals_il_bot","")`) and treats **any** non-command text as a search. In a group that means every message triggers a search. — [bot.py](https://github.com/tzahi1715-cpu/aliexpress-telegram-bot/blob/HEAD/bot.py)
- platoba's per-user limiter: a sliding 60 s window, `max_per_minute=30`, `burst=5`, returning `RateLimit(allowed, remaining, reset_in)`. The README lists "Block/unblock users, enable/disable groups". — [rate_limiter.py](https://github.com/platoba/MultiAffiliateTGBot/blob/HEAD/app/services/rate_limiter.py), [README](https://github.com/platoba/MultiAffiliateTGBot/blob/HEAD/README.md)
- djeddi12: `CacheWithExpiry` with an asyncio.Lock, 1-day expiry for product, link and resolved-URL caches, and a periodic JobQueue cleanup. Handlers: text matching an AliExpress regex, forwarded text, and a separate handler for non-link text. — [app.py](https://github.com/djeddi12/Aliexpress-telegram-bot/blob/HEAD/app.py)
- ismailsaoulaj dedupes posted product IDs in Upstash Redis so restarts do not repost. — [README](https://github.com/ismailsaoulaj/aliexpress-affiliate-bot/blob/HEAD/README.md)
- Telegram limits: "In a single chat, avoid sending more than one message per second … In a group, bots are not be able to send more than 20 messages per minute." — [Bot FAQ](https://core.telegram.org/bots/faq)
- Telegram privacy mode: "By default, all bots added to groups run in Privacy Mode and only see relevant messages and commands" (explicit commands, replies to the bot, and so on). "Privacy mode is enabled by default for all bots, except bots that were added to a group as admins (bot admins always receive all messages)." It can be disabled, but the bot must then be re-added to the group. — [Bot features: privacy mode](https://core.telegram.org/bots/features#privacy-mode)

### Inferences
- For a free-text "חפש לי X" trigger in groups, the bot must be a group admin or have privacy mode disabled in BotFather and be re-added. Otherwise it never sees the trigger.
- In groups, stay silent on non-trigger messages. Reply-to the requester, edit one placeholder message into the result rather than sending several, restrict pagination buttons to the requester (the omerxxben pattern), and add a per-user cooldown plus a per-chat cap to stay under 20 messages/min.
- Cache at least: query (normalized English) → results for minutes to hours, product_id → DS rating and review count for about a day, and product_id → affiliate link.

### Gaps
- No repo implemented a per-group cooldown or quota explicitly tied to Telegram's 20 messages/min group limit. Persisting search state for pagination across restarts (omerxxben keeps it in memory) was also not seen.

## 7. Lessons from issues, README warnings and code: API errors, bans, ToS, common mistakes

### Takeaway
The recurring failures are leaked credentials, dead endpoints, unhandled per-app-key rate limits (`ApiCallLimit`), intermittent "publisher not registered" 401s, mislabeled rating fields, blocking I/O in async bots, and spammy group behavior. There are also ToS risks: rotating two app keys to dodge limits, user-session (Telethon) relays, and undocumented sourceType tricks. I found no AliExpress-specific ban reports.

### Cited Findings
- **Hardcoded secrets committed to public repos** (I saw the Telegram bot tokens, AliExpress app keys and secrets, and a DS access_token in source): MiilouDz `bot.py`, tzahi1715 `bot.py`, and omerxxben's DS `access_token` hardcoded in `ali_epress_api_products.py`. SaulloGabryel/BlueBot committed an entire browser profile directory (`Affiliates/User Data/...`, including cache, autofill and wallet DBs). — [MiilouDz bot.py](https://github.com/MiilouDz/Aliexpress-Affiliate-Telegram-Bot/blob/HEAD/bot.py), [tzahi bot.py](https://github.com/tzahi1715-cpu/aliexpress-telegram-bot/blob/HEAD/bot.py), [omerxxben products](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/ali_epress_api_products.py), [BlueBot tree](https://github.com/SaulloGabryel/BlueBot)
- **Broken code in the most-starred bot**: MiilouDz's `get_affiliate_links` references undefined `affiliate_link` and `super_links`, `extract_link` calls `re.findall(link_pattern)` without the text argument, `btn3` is used before it is defined, and bare `except:` hides it all behind "حدث خطأ". — [bot.py](https://github.com/MiilouDz/Aliexpress-Affiliate-Telegram-Bot/blob/HEAD/bot.py)
- **Dead endpoints**: the old TOP gateway raised "Platform System blacklist: Taobao Open Platform (TOP) has been offline" (issue opened 2023-09-25, unanswered). Current bots use `https://api-sg.aliexpress.com/sync`. davenewham still targets `gw.api.alibaba.com/openapi/.../portals.open/`. — [issue #24](https://github.com/sergioteula/python-aliexpress-api/issues/24), [omerxxben GLOBAL_CONST](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/GLOBAL_CONST.py), [davenewham](https://github.com/davenewham/telegram-aliexpress-bot/blob/HEAD/telegram_aliexpress_bot/aliexpress_api.py)
- **401 "This publisher is not registered" / 404 "System Error"**: the maintainer's answer is that you must create an app at openservice.aliexpress.com, get approved, and "request API access after adding your app". A 2025-10-22 comment reports the error happening **randomly**: "Sometimes the API works and sometimes not". — [issue #34](https://github.com/sergioteula/python-aliexpress-api/issues/34)
- **Rate limits are per app key**: "Measured 2026-08-09: ~10% of calls return `{"error_response":{"code":"ApiCallLimit","msg":"...this ban will last 1 seconds"}}` … sequentially, so it is the app key's own quota, not our concurrency." Treating that as an empty result caused live products to show "Product not found" after CDN caching. The fix: a max of 4 in flight, re-sign each retry (the timestamp is part of the signature), and one retry after 1.2 s. — [lib/aliexpress.ts](https://github.com/ohadf2015/shopli/blob/HEAD/lib/aliexpress.ts)
- omerxxben works around ApiCallLimit by **failing over to a second app key** (`SECOND_APP_KEY`/`SECOND_APP_SECRET`) and returns "no api available" when both are exhausted. — [ali_epress_api.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/ali_epress_api.py), [GLOBAL_CONST.py](https://github.com/omerxxben/telegram_bot/blob/HEAD/Classes/GLOBAL_CONST.py)
- **Missing API features** users keep asking for: shipping fees (issue #36, 2025, partial PRs #38/#41), DS API support (#44), and image search (#43). — [issue #36](https://github.com/sergioteula/python-aliexpress-api/issues/36), [issues list](https://github.com/sergioteula/python-aliexpress-api/issues)
- **Misleading copy**: tzahi1715 hardcodes "🚚 משלוח חינם! 🎁" and random urgency phrases ("⏰ מלאי מוגבל - הזדרזי!") on every product regardless of data, and converts USD at a fixed 3.7. — [bot.py](https://github.com/tzahi1715-cpu/aliexpress-telegram-bot/blob/HEAD/bot.py)
- **Currency bug class**: shopli notes a region config that "fell through to the EU default and priced every product in EUR under a ₪ header". danielrosehill's validation checklist treats "a USD figure reported as ILS" as "the worst failure available". — [shopli lib/aliexpress.ts](https://github.com/ohadf2015/shopli/blob/HEAD/lib/aliexpress.ts), [fetch-listing SKILL](https://github.com/danielrosehill/Aliexpress-Israel-Skills/blob/HEAD/skills/fetch-listing/SKILL.md)
- **Small-sample ratings**: "a 4.9 on 12 orders is not a 4.9 on 12,000". Also, a "strong global rating with zero IL reviews means nobody has proven this ships here". — [fetch-listing SKILL](https://github.com/danielrosehill/Aliexpress-Israel-Skills/blob/HEAD/skills/fetch-listing/SKILL.md)
- **Anti-bot on scraping paths** (Oct 2026): MTop reCAPTCHA on fresh sessions, Baxia/TMD challenges, and the need for residential proxies. — [fetchaller site-apis.md](https://github.com/Averyy/fetchaller-mcp/blob/HEAD/docs/site-apis.md), [Apify actor](https://apify.com/xtracto/aliexpress-review-scraper.md)
- **Telegram-side policy**: Telegram's own affiliate-program ToS (for Telegram's program, not AliExpress's) prohibits "spamming or flooding chats with the affiliate link" and automated engagement inflation, with possible termination of the channel or account. This is a useful analogue for group-spam risk. — [Telegram affiliate ToS](https://telegram.org/tos/affiliate-program)
- Lap4Dev relies on a Telethon **user account** session (an `anon.session` file) rather than the Bot API, to read and repost channels. — [README](https://github.com/Lap4Dev/tg-ali-forward/blob/HEAD/README.md)

### Inferences
- Use env and secret storage, never commit `.env`. mouad73's OPERATIONS.md ("Never commit that file … Do not print or paste the bot token") is the good counter-example.
- Wrap every Open Platform call with the following:
  - detect `error_response`
  - for `ApiCallLimit`, re-sign the request, back off briefly, and retry once
  - treat any other error as "unavailable", not "no results", and never cache it
  - have a global concurrency cap per app key
- Rotating multiple app keys to evade quotas and scraping review endpoints may conflict with AliExpress Open Platform terms. I did not verify the actual terms text, so this is a risk to check, not a confirmed violation.

### Gaps
- I could not locate the AliExpress Portals / Open Platform affiliate terms text about bots, automated link generation, or the use of undocumented endpoints. I also found no first-hand reports of affiliate accounts banned for Telegram bot usage.
- I found no published numeric daily or per-second quota for affiliate app keys. shopli only observed about 10% `ApiCallLimit` responses with a 1 s ban in sequential calls.
