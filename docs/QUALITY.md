# איך בודקים שהבוט תקין – כל הכלים

מה כל כלי תופס, מתי מריצים אותו, ואיך.

## 1. בדיקות אוטומטיות (`npm test`)
- **מה זה:** 138 בדיקות שרצות בלי רשת ובלי מפתחות: טריגרים, שתיקה בקבוצה, כרטיס, קישורים, יועץ, הגנה על הקבוצה, webhook, פרטיות הלוגים.
- **מתי:** בכל שינוי בקוד. GitHub מריץ אותן לבד בכל העלאה (`.github/workflows/daily-check.yml`).
- **מה זה לא תופס:** תקלות אצל ספקים חיצוניים (AI, עלי אקספרס).

## 2. בדיקה חיה של כל הספקים (`npm run check:live`)
- **מה זה בודק:** AI (תיקון כתיב וזיהוי "לא מוצר"), חיפוש אמיתי בעלי אקספרס (שקלים וקישורים קצרים), יצירת קישור שותפים, והאם השרת ב-Render ער ולא במצב דמו (עם `SERVER_URL`).
- **מתי:** אוטומטית כל בוקר ב-08:00 ב-GitHub Actions. אם משהו נכשל, GitHub שולח לך מייל. אפשר גם להריץ ידנית.
- **מה הוא היה תופס:** את המודל שהוצא משימוש ב-23.10, תוך יום ולא אחרי שעות של תוצאות גרועות.
- **דרישה:** 4 סודות ב-GitHub (ראו "הגדרה" למטה).

## 3. איכות החיפוש מקצה לקצה (`npm run eval:search`)
- **מה זה:** 15 חיפושים אמיתיים. AI שני ("שופט", gpt-6-luna) בודק אם כל אחד מ-4 המוצרים הוא באמת מה שביקשו.
- **המדד (45 חיפושים):** כמה מתוך 4 המוצרים הם המוצר הנכון, וכמה מתאימים לכל התכונות שביקשו.
  - 23.10: **85%** מוצר נכון.
  - 24.10, אחרי הסינון לשתי דרגות (מדויק / חלקי): **92%** מוצר נכון, **73%** עם כל התכונות, 0 חיפושים עם פחות מ-4 תוצאות.
  - עדיין חלשים: "כיסוי לאייפד פרחוני", "משקולות 5 קילו", "בקבוק עם מסנן".
- **מתי:** לפני ואחרי כל שינוי בחיפוש, ב-AI או בסינון, כדי לראות אם שיפרנו או קלקלנו. עולה פחות מסנט.

## 4. הבנת הבקשה בלבד (`npm run eval:query`)
16 בקשות בעברית ← סטטוס, מילות חיפוש ותקציב, מול תשובות צפויות. אפשר להשוות מודלים: `npm run eval:query -- --model gpt-6-luna`.

## 5. דוח מצב בטלגרם (`/status`)
- **מה זה מראה:** גרסה (commit), כמה זמן השרת פעיל, מספר החיפושים, כמה הסתיימו בלי תוצאות, שגיאות עלי אקספרס, כשלי AI וטלגרם, השגיאות האחרונות, ובדיקה חיה של ה-AI ועלי אקספרס.
- **רק לבעלים:** בצ'אט פרטי, עם `ADMIN_USER_ID` מוגדר.
- **בונוס:** הגרסה בדוח מראה אם Render כבר מריץ את העדכון האחרון.

## 6. התראות אוטומטיות לבעלים
אם אותה תקלה קורית 3 פעמים תוך 10 דקות (AI, עלי אקספרס או טלגרם), הבוט שולח לך הודעה פרטית, לכל היותר פעם בשעה לכל סוג תקלה. דורש `ADMIN_USER_ID`.

## 7. בדיקה ידנית בטלגרם
`docs/TEST_PLAN.md`: כ-90 בדיקות לפי תחום, כולל טלפון, יועץ, הגנה על הקבוצה ועמלות.

## 8. מקורות חיצוניים לבדוק מדי פעם
| מה | איפה | מה לחפש |
|---|---|---|
| לוגים של השרת | Render ← Logs | שורות `failed`. אף פעם לא אמור להופיע טקסט של הודעות |
| עמלות | AliExpress Portals ← Reports, לפי Tracking ID `panda_bot` | קליקים והזמנות |
| עלות AI | OpenAI ← Usage | סנטים ביום |
| מודלים שיוצאים משימוש | https://platform.openai.com/docs/deprecations | `gpt-5.4-nano` |

## הגדרה (פעם אחת)
1. **`ADMIN_USER_ID`:** שולחים לבוט בפרטי `/myid`, ואת המספר שחוזר מוסיפים ב-Render ← Environment.
2. **סודות ב-GitHub לבדיקה היומית:** מריצים בטרמינל, בתיקיית הפרויקט. הערכים עוברים ישר מקובץ `.env` ל-GitHub, בלי להופיע על המסך:
   ```bash
   for k in OPENAI_API_KEY ALI_APP_KEY ALI_APP_SECRET ALI_TRACKING_ID; do grep "^$k=" .env | cut -d= -f2- | tr -d '\n' | gh secret set "$k"; done
   ```
3. **הרצה ראשונה ידנית:** GitHub ← Actions ← Daily check ← Run workflow.
